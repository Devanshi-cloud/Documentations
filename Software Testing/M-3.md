# 🧠 Testing Types – My Notes (Simple & Crisp Understanding)

I always think of testing as a layered approach:
Small → Connected → Full System → Real Users

---

# 🔧 1. Unit Testing

## Definition
I test individual functions or components in isolation.

## My Understanding
I check if each small piece of code works correctly on its own.

## Analogy
Car factory example:
- Engine tested separately
- Brakes tested separately
- Headlights tested separately

## Example
Testing:
`calculate_discount(price, coupon)`

## Key Idea
- Test small
- Fail fast
- Fix early

---

# 🔗 2. Integration Testing

## Definition
I test interaction and data flow between modules.

## My Understanding
I check if different working parts communicate properly.

## Analogy
Lego blocks:
- Each block works fine alone
- But do they fit together properly?

Restaurant example:
- Chef prepares food
- Waiter delivers
- If communication fails → customer suffers

---

# 🌐 3. System Testing

## Definition
I test the complete integrated system.

## My Understanding
I check full end-to-end flow like a real user.

## Example (E-commerce)
- Login → Search → Cart → Payment → Order confirmation

---

# 🧑‍💼 4. UAT (User Acceptance Testing)

## Definition
Real users validate the system against business needs.

## My Understanding
I check if the system is acceptable for actual users.

## Key Question
“Would real users accept this product?”

---

# 🚀 5. Alpha Testing

## Definition
Internal testing done before release.

## My Understanding
I test inside the company environment before users see it.

---

# 🌍 6. Beta Testing

## Definition
Testing done by real users in real environment.

## My Understanding
I release system to limited users and collect feedback.

---

# ⚡ 7. Smoke Testing

## Definition
Quick check to verify build stability.

## My Understanding
I check if the system is stable enough to test further.

## Example
- App launches
- Login works
- Homepage loads

If smoke fails → I stop testing immediately

---

# 🧼 8. Sanity Testing

## Definition
Quick check after bug fix or small change.

## My Understanding
I verify that the specific fix is working properly.

## Example
- Payment bug fixed → I only test payment flow

---

# 🔁 9. Regression Testing

## Definition
Re-testing existing features after changes.

## My Understanding
I ensure new changes don’t break old working features.

## Example
After adding coupon feature:
- I re-check login, cart, checkout, payment

---

# 🧠 FINAL MENTAL MODEL

I visualize testing like this:

Unit → Integration → System → UAT  
Small → Connected → Full App → Real Users

Supporting checks:
- Smoke → Is build stable?
- Sanity → Did fix work?
- Regression → Did anything break?

---

# 🧾 ONE-LINE SUMMARY

- Unit → I test small code pieces  
- Integration → I test connections  
- System → I test full application  
- UAT → I test with users  
- Alpha → Internal testing  
- Beta → Real user testing  
- Smoke → Basic stability check  
- Sanity → Quick fix verification  
- Regression → Ensure nothing broke
